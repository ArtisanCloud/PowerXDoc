# 主用例说明：线索捕获与去重（Lead Capture & Deduplication）

## 背景概述

PowerX CRM 需要面对来自官网、线下活动、合作渠道等多源线索的持续涌入。如果缺乏标准化的接入与去重机制，销售团队会被重复信息淹没，隐私合规也难以保障。本主用例聚焦“线索捕获与去重”全链路，确保线索在进入系统的瞬间即可完成格式校验、重复检测、权限过滤与自动分配，把高价值线索快速送达到合适的销售人员手中。

## 目标与价值
- **全渠道接入**：统一表单、导入、API 等方式进入同一数据管道，降低线索遗漏风险。
- **高精度去重**：通过手机号、邮箱、企业信息等多字段匹配，避免销售重复跟进。
- **合规防护**：在接入阶段即执行 NDA、字段授权等校验，确保数据传递安全。
- **智能分配**：线索进入系统后立即按地域、行业、优先级自动指派，提高响应速度。
- **可审计化**：完整记录线索来源、处理动作与责任人，便于复盘与追责。

## 参与角色
- **市场运营人员**：设计与维护线索收集渠道、活动表单与导入模板。
- **渠道合作伙伴**：通过合作门户批量上传线索，与企业共享商机。
- **销售负责人**：根据业务策略配置分配规则与优先级。
- **客户隐私合规团队**：制定敏感字段授权策略与 NDA 检查规则。
- **智能 Agent / 自动化流程**：负责字段识别、去重、分配及告警等自动任务。

## 主场景 User Story
> **作为** 市场与销售协同团队，**我希望** 无论线索从哪个渠道进入都能被准确去重并快速分配给合适的销售，**从而** 提升首次响应效率并减少重复跟进带来的客户体验损失。

## 子场景详解

### 子场景 A：官网表单线索自动去重入库
- **角色与触发**：市场同事通过 Web 表单收集线索后，系统自动校验重复手机号并合并记录。
- **主要流程**：
  1. 客户在官网填写表单提交线索，包含姓名、手机号、邮箱、公司等信息。
  2. 系统实时调用去重服务，对关键字段（手机号、邮箱、企业税号）进行模糊匹配。
  3. 如果识别为重复线索，系统合并历史记录并追加最新行为标签；若为新线索则创建档案。
  4. 入库成功后触发通知，推送给匹配的销售负责人或线索培育流程。
- **成功标准**：去重命中率达到设定阈值；新旧线索均在 1 分钟内入库；通知准确送达。
- **异常与风控**：字段缺失时自动回退到待补全队列；重复判断冲突需人工复核；防止恶意灌入脚本。
- **指标建议**：线索入库时延、重复线索占比、手工复核比率、拒绝/黑名单命中率。

### 子场景 B：线下活动名片识别与字段归一
- **角色与触发**：线下活动导入的名片数据由 Agent 自动识别关键字段并归档至待跟进池。
- **主要流程**：
  1. 市场团队将名片照片或 Excel 导入 CRM，选择对应活动标签。
  2. Agent OCR 识别名片信息并与企业名称库匹配，自动补齐行业、规模等属性。
  3. 系统校验字段格式（手机号、邮箱、职位），不合规的记录回到人工校正队列。
  4. 处理完成的线索写入活动专属池，等待后续培育与分配。
- **成功标准**：识别准确率达到目标；字段格式统一；活动标签完整关联。
- **异常与风控**：模糊识别字段需人工审核；导入失败提供错误报告；防止重复导入同一文件。
- **指标建议**：OCR 识别准确率、人工校正占比、活动转化跟踪效率。

### 子场景 C：渠道伙伴上传线索的保密校验
- **角色与触发**：渠道合作伙伴上传线索时触发保密协议校验，未经授权的字段会被遮蔽。
- **主要流程**：
  1. 渠道伙伴在合作门户上传线索文件并选择共享等级。
  2. 系统根据合作协议加载字段授权矩阵，自动判断哪些字段需掩码。
  3. 对未签署 NDA 的伙伴，系统拒绝含敏感字段的线索并要求补全流程。
  4. 合规上传的线索写入共享池，并记录伙伴信息与权益分配条款。
- **成功标准**：未经授权的字段全部被遮蔽；合规记录完整留痕；违规上传及时拦截。
- **异常与风控**：异常字段触发告警；伙伴账号权限变更需实时同步；生成月度合规报告。
- **指标建议**：合规拦截率、伙伴上传成功率、违规响应时间。

### 子场景 D：线索自动分配与通知
- **角色与触发**：线索分配策略根据销售区域与行业自动匹配负责人，并通知到个人任务箱。
- **主要流程**：
  1. 系统读取线索的地域、行业、线索评分等属性，与分配规则引擎匹配。
  2. 自动将线索指派给最佳负责人或备选队列，并设置处理 SLA。
  3. 新负责人在桌面或移动端收到通知，系统创建待办任务和跟进建议。
  4. 若在 SLA 内无响应，线索自动升级或重新分配，同时记录处理日志。
- **成功标准**：分配准确度高；通知及时；线索在 SLA 内获得初次响应。
- **异常与风控**：规则冲突时采用优先级或轮询策略；离职人员的线索自动回收；生成分配公平性报表。
- **指标建议**：首次响应时间、线索派单准确率、SLA 逾期率、线索回收占比。

## 场景级测试用例示例

> 测试准备：搭建 CRM 沙箱，启用 Web 表单、渠道伙伴门户、OCR 服务与线索去重引擎。预置 3 条历史线索（含重复手机号/邮箱）、1 个线下活动模板、2 个渠道伙伴账号，配置华东/华南销售团队与自动化分配规则。

### 用例 A-1：官网表单线索自动去重（正向）
- **前置条件**：历史线索库已有手机号 13800000001；Web 表单启用必填校验。
- **操作步骤**：
  1. 在官网表单填写与历史线索相同手机号但不同姓名的线索信息。
  2. 提交表单，观察去重引擎处理结果。
  3. 登录 CRM 核对线索档案。
- **预期结果**：
  - 系统判定为重复线索，合并历史记录并追加“官网二次提交”标签。
  - 不创建新线索编号，时间线新增一次访问行为。
  - 销售负责人收到二次提交通知，待办中无需再次拨打欢迎电话。

### 用例 B-1：线下活动名片 OCR 识别（正向）
- **前置条件**：活动“2025 春季峰会”开启；OCR 服务可用。
- **操作步骤**：
  1. 通过活动导入界面上传 10 张名片照片。
  2. 校验姓名/职位/手机号在导入预览中的识别结果。
  3. 完成导入并查看活动线索池。
- **预期结果**：
  - OCR 识别成功率 ≥ 80%，异常字段标注为黄色待人工确认。
  - 通过校正保存后写入活动线索池，并附带标签“2025 春季峰会”。
  - 系统自动生成导入报告，列出需人工补录的字段清单。

### 用例 C-1：渠道伙伴上传敏感字段拦截（逆向）
- **前置条件**：渠道伙伴“华南代理”尚未签署 NDA；其账号拥有上传权限。
- **操作步骤**：
  1. 伙伴上传包含客户营业执照号、合同金额的 Excel。
  2. 提交后查看上传结果与系统告警。
- **预期结果**：
  - 系统拒绝导入，提示“请完成 NDA 签署后再上传敏感字段”。
  - 导入记录状态为“已拦截”，日志记录触发的合规策略编号。
  - 管理员收到合规告警通知，可引导伙伴补充流程。

### 用例 D-1：线索智能分配 SLA 监控（正向）
- **前置条件**：华东区域销售“张三”可用；SLA 设置为首次响应 2 小时。
- **操作步骤**：
  1. 导入 5 条来自上海的高分线索。
  2. 观察智能分配结果及张三待办列表。
  3. 超过 2 小时仍未响应，验证升级策略。
- **预期结果**：
  - 线索自动指派给张三，并创建“首次联系”任务，截止时间为创建后 2 小时。
  - 若张三在 SLA 前反馈“已联系”，任务自动完成。
  - 超时未处理时，线索状态标记“待升级”，自动转派给主管并记录升级原因。

### 用例 D-2：离职人员线索自动回收（逆向）
- **前置条件**：销售“李四”在系统中标记为离职；仍有 3 条线索指派给他。
- **操作步骤**：
  1. 触发分配引擎刷新任务（手动或定时）。
  2. 查看线索指派结果与通知。
- **预期结果**：
  - 系统检测到离职状态，自动将线索回收至公共线索池。
  - 触发引擎重新分配给同区域可用销售，并保留原始跟进日志。
  - 人力或销售主管收到回收确认通知，避免线索遗失。
