# 主用例说明：拜访打卡与轨迹管理（Location Check-in & Visit Tracking）

## 背景概述

线下拜访仍是许多 B2B/B2C 场景的关键环节。企业需要掌握销售拜访计划、到访情况、拜访成果，避免虚假拜访或漏报。本主用例聚焦企业微信移动端的拜访打卡、轨迹记录、任务协同与复盘机制，帮助前线团队高效开展外勤工作。

## 目标与价值
- **真实记录**：定位打卡、照片、备注确保拜访真实性。
- **任务协同**：拜访计划与目标客户关联，执行情况实时同步。
- **复盘改进**：拜访内容、反馈沉淀为客户档案与行动计划。
- **安全合规**：轨迹数据受控，保护隐私并满足审计要求。

## 参与角色
- **销售/客户成功**：执行拜访、提交纪要。
- **销售主管**：审核计划、查看执行、提供辅导。
- **运营团队**：根据拜访反馈优化活动与策略。
- **数据与合规**：管理定位数据权限、安全。

## 主场景 User Story
> **作为** 销售人员，**我希望** 在企业微信移动端快速完成拜访打卡与纪要记录，**从而** 提升执行效率并保证数据真实。

## 子场景详解

### 子场景 A：拜访计划与提醒
- **角色与触发**：销售在周初制定拜访计划。
- **主要流程**：
  1. 在 SCRM 选择目标客户，创建拜访任务（时间、地点、目标）。
  2. 系统同步至企业微信日历并发送提醒。
  3. 支持批量导入线路规划。
  4. 主管审批重点拜访并提供指导。
- **成功标准**：计划清晰；提醒及时；主管可视化。
- **异常与风控**：冲突提醒；未审批无法执行；记录修改历史。
- **指标建议**：计划覆盖率、审批时长、拜访执行率。

### 子场景 B：现场打卡与轨迹记录
- **角色与触发**：销售到达客户地点。
- **主要流程**：
  1. 打开移动端一键“到访打卡”，自动获取 GPS 和时间。
  2. 可上传现场照片、文件或扫描签到码。
  3. 系统记录轨迹点，用于行程审核（可选）。
  4. 离开时完成“结束打卡”，记录拜访时长。
- **成功标准**：定位准确；打卡便捷；数据可信。
- **异常与风控**：定位异常可手动补充但需主管审批；隐私保护可设置模糊精度；轨迹数据加密存储。
- **指标建议**：打卡成功率、异常率、审批耗时。

### 子场景 C：拜访纪要与任务生成
- **角色与触发**：拜访结束后需记录结果。
- **主要流程**：
  1. 销售填写拜访纪要（需求、问题、竞争信息）。
  2. 可通过语音转写快速完成，并附加照片、文档。
  3. 根据纪要自动生成后续任务（报价、演示、方案）。
  4. 纪要同步到客户档案、商机、团队看板。
- **成功标准**：纪要全面；任务自动生成；团队同步。
- **异常与风控**：纪要未提交无法结束拜访；敏感信息脱敏；主管可点评。
- **指标建议**：纪要提交率、任务完成率、客户满意度变化。

### 子场景 D：拜访复盘与辅导
- **角色与触发**：主管定期复盘拜访执行。
- **主要流程**：
  1. 查看拜访执行率、轨迹、纪要质量。
  2. 识别异常（虚假打卡、频次不足、成果低）。
  3. 安排辅导或陪访，记录改进计划。
  4. 输出复盘报告，沉淀最佳路线与话术。
- **成功标准**：复盘及时；辅导有效；数据支撑决策。
- **异常与风控**：轨迹数据仅授权人员可查看；复盘总结保留；支持导出。
- **指标建议**：复盘完成率、辅导覆盖率、改进效果。

## 场景级测试用例示例

> 测试准备：配置拜访计划模板、GPS 打卡功能、语音转写、轨迹权限、复盘看板。

### 用例 A-1：现场打卡与纪要（正向）
- **前置条件**：销售计划拜访客户 A。
- **操作步骤**：
  1. 到达现场后打卡并上传照片。
  2. 拜访结束提交纪要。
- **预期结果**：
  - 打卡成功记录时间、坐标、照片。
  - 纪要同步至客户档案并生成后续任务。
  - 主管查看看板确认执行情况。

### 用例 B-1：定位异常审批（逆向）
- **前置条件**：模拟 GPS 信号弱。
- **操作步骤**：
  1. 打卡失败提示“定位异常”。
  2. 手动补录信息提交审批。
- **预期结果**：
  - 系统记录异常并发送审批任务给主管。
  - 审批通过后数据纳入统计；若拒绝则标记为异常拜访。
  - 日志留痕便于审计。
