# 主用例说明：标签冲突与权重治理（Tag Conflict & Weight Governance）

## 背景概述

当标签数量越来越多、来源多样（行为、模型、人工），不可避免出现冲突：同一客户被贴上“高客单价”与“价格敏感”“黑名单”等矛盾标签。没有治理会导致旅程逻辑紊乱、合规风险。本主用例围绕标签冲突识别、权重策略、人工审批与审计，确保标签体系健康。

## 目标与价值
- **冲突识别**：自动侦测互斥标签或逻辑矛盾。
- **优先级策略**：按照权重、来源可信度确定最终标签。
- **审批与留痕**：敏感冲突需人工复核并记录。
- **合规控制**：关键标签受控，避免误触达和违规。

## 参与角色
- **标签运营团队**：制定冲突规则、权重策略、审批流程。
- **业务团队**：提出标签需求、了解冲突结果。
- **合规与安全**：审核敏感标签与冲突处理。
- **IT/中台**：实现冲突检测、日志、通知。
- **数据团队**：提供标签来源可信度评估。

## 主场景 User Story
> **作为** 标签运营负责人，**我希望** 自动识别与处理标签冲突，**从而** 确保业务逻辑清晰并降低风险。

## 子场景详解

### 子场景 A：冲突规则库建设
- **角色与触发**：需要定义互斥/覆盖关系。
- **主要流程**：
  1. 梳理标签目录，识别互斥关系（如“黑名单” vs “VIP”）。
  2. 配置冲突规则（互斥、优先级、覆盖、合并）。
  3. 设定权重计算方法：来源可信度、更新时间、模型置信度。
  4. 发布规则并每周迭代。
- **成功标准**：规则清晰；覆盖关键标签；容易维护。
- **异常与风控**：规则冲突时系统提示；版本控制；权限限制。
- **指标建议**：规则覆盖率、更新频次、冲突检测准确率。

### 子场景 B：冲突检测与自动处理
- **角色与触发**：系统定时或实时扫描标签。
- **主要流程**：
  1. 标签更新时触发冲突检测。
  2. 根据权重策略决定保留、覆盖或合并的标签。
  3. 输出处理结果并写入客户画像。
  4. 对需人工复核的冲突创建审批任务。
- **成功标准**：检测及时；处理逻辑透明；结果可追溯。
- **异常与风控**：处理失败回滚；疑似错误触发人工复核；提供重算能力。
- **指标建议**：冲突处理成功率、自动化率、复核量。

### 子场景 C：人工复核与合规审批
- **角色与触发**：涉及敏感标签、重要客户。
- **主要流程**：
  1. 冲突结果为“需复核”时自动生成工单。
  2. 复核人查看标签来源、历史记录、建议操作。
  3. 审批通过后更新标签并记录原因。
  4. 审计日志保存操作详情，为合规检查提供依据。
- **成功标准**：审批及时；结果可解释；合规可回溯。
- **异常与风控**：超时自动升级；复核意见冲突时引入更高权限审批；敏感操作需二次确认。
- **指标建议**：复核完成时长、通过率、审计抽检合格率。

### 子场景 D：冲突治理报告与反馈
- **角色与触发**：定期评估冲突治理成效。
- **主要流程**：
  1. 生成冲突统计报告（次数、标签、来源）。
  2. 分析根因：规则缺陷、数据源问题、业务策略变化。
  3. 更新规则、教育业务团队或调整数据源。
  4. 将治理经验纳入标签使用白皮书。
- **成功标准**：冲突量下降；根因清晰；业务理解提升。
- **异常与风控**：报告数据异常需复查；隐私数据脱敏；分享范围受限。
- **指标建议**：冲突发生率、重复冲突率、问题解决率。

## 场景级测试用例示例

> 测试准备：配置冲突规则库、模拟标签数据、审批流程、审计日志。

### 用例 A-1：自动冲突处理（正向）
- **前置条件**：客户同时打上“VIP”“黑名单”标签；规则：黑名单优先。
- **操作步骤**：
  1. 运行冲突检测任务。
  2. 查看客户最终标签。
- **预期结果**：
  - 系统保留“黑名单”，禁用“VIP”，并记入日志。
  - 触发合规通知相关负责人。
  - 同步旅程暂停对该客户的营销触达。

### 用例 B-1：复核超时升级（逆向）
- **前置条件**：冲突记录需复核，复核人超时未处理。
- **操作步骤**：
  1. 模拟冲突并指定复核人。
  2. 等待超时。
- **预期结果**：
  - 系统自动升级至主管并发送提醒。
  - 冲突在处理前保持“冻结”状态，避免错误使用。
  - 审计记录标记为“超时升级”。
