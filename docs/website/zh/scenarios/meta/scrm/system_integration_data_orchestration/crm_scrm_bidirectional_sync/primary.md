# 主用例说明：CRM 与 SCRM 双向同步（CRM & SCRM Bidirectional Sync）

## 背景概述

社交触点产生的线索、客户互动、服务记录需要沉淀到企业 CRM 才能形成完整的客户资产；同时 CRM 中的商机、客户层级、负责人调整也需要第一时间反馈到企业微信前线。若缺乏双向同步，容易出现重复跟进、信息延迟、客户体验割裂。本主用例聚焦 CRM 与 SCRM 的实时双向同步机制，确保“前线触点与后台资产”统一。

## 目标与价值
- **单一客户视图**：所有社交数据与 CRM 主数据保持一致，避免重复创建或缺失信息。
- **实时协同**：商机进展、负责人变更等关键状态可即时通知前线人员。
- **质量保障**：通过数据中台治理、异常补偿、版本控制保障同步可靠。
- **扩展能力**：考虑多系统场景，支持插件化接入与灵活配置。

## 参与角色
- **数据中台/集成团队**：设计数据模型与同步流程，监控任务运行。
- **销售与客户成功团队**：使用同步后的数据开展跟进、服务。
- **客服运营**：依赖 CRM 信息在社交端提供一致的体验。
- **IT 运维**：处理同步任务的异常与性能调优。
- **安全与合规**：审核数据同步范围与安全策略。

## 主场景 User Story
> **作为** 数据集成负责人，**我希望** 建立 CRM 与 SCRM 的实时双向同步，**从而** 让前线和后台共享统一客户信息，并减少手工对账。

## 子场景详解

### 子场景 A：社交流量线索写入 CRM
- **角色与触发**：社交侧新增线索或客户信息更新。
- **主要流程**：
  1. 用户扫码、留资或参与社群活动，SCRM 生成线索记录。
  2. 数据同步服务将线索推送至 CRM，校验去重规则并生成统一客户 ID。
  3. 同步成功后反馈 SCRM 更新状态，展示 CRM 线索编号。
  4. 失败记录进入补偿队列并告警，允许人工重试或修改数据。
- **成功标准**：线索同步成功率高，CRM 可见渠道来源；处理延迟在 SLA 内。
- **异常与风控**：重复线索自动合并；字段缺失时提示补齐；异常失败保留重试日志。
- **指标建议**：线索同步成功率、延迟、补偿率。

### 子场景 B：CRM 商机与客户变更回写 SCRM
- **角色与触发**：销售在 CRM 中更新商机阶段或更换负责人。
- **主要流程**：
  1. CRM 触发事件，将商机阶段、金额、预计成交等关键字段推送给 SCRM。
  2. SCRM 更新企业微信侧的客户卡片、跟进计划与提醒。
  3. 若负责人变更，自动发起客户好友与群聊交接流程。
  4. 变更通知推送给原负责人、继任者与主管，确保无缝衔接。
- **成功标准**：商机状态在社交端与 CRM 保持一致；更换负责人时客户无感知。
- **异常与风控**：回写失败自动重试；冲突版本采用最新时间戳或人工复核；敏感字段需脱敏。
- **指标建议**：商机回写成功率、负责人交接完成率、通知触达率。

### 子场景 C：主数据与标签对齐
- **角色与触发**：CRM 调整客户等级、行业、关键标签。
- **主要流程**：
  1. 主数据服务监听 CRM 变更，实时推送到 SCRM。
  2. SCRM 更新客户画像、群标签、消息策略。
  3. 对特定标签触发自动旅程或提醒（如战略客户需要 VIP 服务）。
  4. 定期执行对账，校验双方关键字段是否一致。
- **成功标准**：标签一致性高；策略由数据驱动；对账差异可追踪。
- **异常与风控**：冲突标签采用权重规则解决；字段缺失时记录差异；敏感标签同步需审批。
- **指标建议**：主数据一致率、冲突解决时长、同步频率。

### 子场景 D：数据同步监控与补偿
- **角色与触发**：同步任务出现延迟、失败或数据漂移。
- **主要流程**：
  1. 监控平台实时展示同步队列长度、失败率。
  2. 异常时自动触发补偿任务，重放消息或恢复快照。
  3. 若多次失败升级到运维和数据团队协同处理。
  4. 生成同步健康报告，供管理层评估集成稳定性。
- **成功标准**：异常可及时发现并修复；补偿机制可靠；报告清晰。
- **异常与风控**：补偿失败时启动手工应急方案；数据漂移需回滚；提供只读备份保障查询。
- **指标建议**：失败率、补偿成功率、健康评分。

## 场景级测试用例示例

> 测试准备：构建 CRM 与 SCRM 沙箱、消息队列、数据中台监控；准备去重规则、补偿队列、模拟大批量事件。

### 用例 A-1：社交线索实时写入 CRM（正向）
- **前置条件**：线索字段完整；网络正常。
- **操作步骤**：
  1. 在 SCRM 创建社交线索（包含客户信息、渠道、标签）。
  2. 观察同步日志与 CRM 线索列表。
- **预期结果**：
  - 30 秒内 CRM 生成对应线索，带有渠道与社交标签。
  - SCRM 显示 CRM 线索编号与状态为“已同步”。
  - 监控面板同步成功率提升，日志无错误。

### 用例 B-1：商机回写失败补偿（逆向）
- **前置条件**：故意让 SCRM 回写接口超时。
- **操作步骤**：
  1. 在 CRM 更新商机阶段为“方案确认”。
  2. 查看 SCRM 客户卡片与补偿队列。
- **预期结果**：
  - 初次回写失败并告警，补偿任务自动重试 3 次。
  - 若仍失败，任务进入人工队列，状态“待运维处理”。
  - 处理完成后商机阶段准确展示；日志记录全过程。
