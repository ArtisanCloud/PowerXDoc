# 主用例说明：移动审批与扫码作业（Mobile Approval & Code-based Operations）

## 背景概述

前线团队频繁需要移动审批（客户申请、权限开通、费用报销）和扫码作业（活动签到、物料领取、调查反馈）。传统流程依赖 PC 或纸质方式效率低。本主用例聚焦企业微信移动端的一站式审批与扫码操作，实现“走到哪里都能处理业务”。

## 目标与价值
- **随时审批**：审批流程移动化，压缩处理时长。
- **扫码作业**：线下签到、物料、问卷通过二维码/NFC 完成。
- **流程透明**：审批与扫码结果实时同步到系统。
- **合规可控**：权限、日志、审计、异常处理完善。

## 参与角色
- **业务申请人**：提交审批、发起扫码任务。
- **审批人/主管**：在移动端处理审批、授权。
- **运营/活动团队**：执行现场扫码与数据收集。
- **IT/系统管理员**：配置流程、维护安全。
- **合规/审计**：检查流程合规性与日志。

## 主场景 User Story
> **作为** 审批负责人，**我希望** 在企业微信移动端快速处理审批并支持线下扫码作业，**从而** 提升效率并确保数据准确。

## 子场景详解

### 子场景 A：移动审批流程
- **角色与触发**：销售提交客户限时折扣申请。
- **主要流程**：
  1. 销售在 SCRM 发起审批，系统推送到审批人手机。
  2. 审批人查看客户背景、订单数据、建议。
  3. 一键同意/拒绝，支持填写意见或补充材料。
  4. 审批结果同步到 SCRM、CRM，并通知申请人。
- **成功标准**：审批及时；信息完整；记录可追溯。
- **异常与风控**：审批超时自动升级；敏感审批需双人确认；日志不可篡改。
- **指标建议**：审批时长、通过率、超时率。

### 子场景 B：线下扫码签到与物料发放
- **角色与触发**：线下活动进行签到或派发物料。
- **主要流程**：
  1. 运营提前生成签到二维码或 NFC 标签。
  2. 客户或经销商到场后扫码/刷卡，系统验证身份。
  3. 自动记录签到时间、地点、领取物料信息。
  4. 数据同步到 SCRM 与活动报表。
- **成功标准**：识别准确；速度快；数据完整。
- **异常与风控**：重复扫码提醒；伪造二维码无效；离线状态缓存后上传。
- **指标建议**：签到成功率、物料发放准确率、异常处理时长。

### 子场景 C：移动问卷与反馈收集
- **角色与触发**：活动结束需要收集反馈。
- **主要流程**：
  1. 生成问卷二维码，客户扫码填写。
  2. 实时统计结果，生成可视化报告。
  3. 自动将反馈写入客户档案，触发后续行动。
  4. 负面反馈自动转工单或客服跟进。
- **成功标准**：反馈填写便捷；结果实时；行动闭环。
- **异常与风控**：填写异常识别；防刷机制；数据脱敏。
- **指标建议**：问卷完成率、反馈处理率、满意度变化。

### 子场景 D：异常处理与审计
- **角色与触发**：审批与扫码出现异常。
- **主要流程**：
  1. 系统记录所有审批与扫码操作日志。
  2. 异常（重复审批、无权限扫码）触发告警。
  3. 审计团队可查询操作记录，生成报告。
  4. 提供一键冻结流程或撤销操作的能力。
- **成功标准**：日志完整；异常可追溯；审计便捷。
- **异常与风控**：日志存储加密；撤销需审批；保留 7*24 支持。
- **指标建议**：异常检测率、审计处理时长、撤销率。

## 场景级测试用例示例

> 测试准备：配置审批流程、二维码生成器、NFC、问卷系统、日志审计工具。

### 用例 A-1：移动审批成功（正向）
- **前置条件**：审批人已在移动端授权。
- **操作步骤**：
  1. 销售发起折扣审批。
  2. 审批人在手机上处理。
- **预期结果**：
  - 审批人可查看完整背景并一键通过。
  - 结果即时通知申请人并写入系统。
  - 日志记录审批全过程。

### 用例 B-1：重复扫码拦截（逆向）
- **前置条件**：活动要求每人只能领取一次物料。
- **操作步骤**：
  1. 同一人重复扫码。
  2. 查看系统处理。
- **预期结果**：
  - 第二次扫码提示“已领取”，不再发放。
  - 记录异常尝试并通知现场负责人。
  - 数据报表仅统计一次领取。
