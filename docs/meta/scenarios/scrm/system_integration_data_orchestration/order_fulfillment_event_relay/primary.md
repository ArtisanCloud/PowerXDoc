# 主用例说明：订单与履约事件推送（Order & Fulfillment Event Relay）

## 背景概述

订单从生成、支付、发货到售后，在多个系统之间流转。若订单状态无法及时反馈给企业微信前线，客户会频繁咨询，销售与客服也难以及时响应。本主用例关注“订单事件到社交触点”的即时推送与协同，包括发货通知、异常预警、售后进度等，确保客户旅程信息透明，提升体验与效率。

## 目标与价值
- **客户体验一致**：订单状态即时通知客户，减少人工询问。
- **内部协同顺畅**：销售、客服、履约团队同步了解订单进度。
- **风险可控**：订单异常自动升级处理，避免延迟放大。
- **数据闭环**：订单事件反哺运营分析与复购策略。

## 参与角色
- **订单/电商系统**：产生订单状态、物流、售后事件。
- **履约/仓储团队**：处理发货、异常与补货。
- **客服团队**：在社交渠道回答客户问题、处理售后。
- **销售与客户成功**：关注重点客户订单、及时跟进。
- **数据团队**：分析订单事件与客户行为，优化策略。

## 主场景 User Story
> **作为** 客户服务负责人，**我希望** 订单与履约事件能够实时推送到企业微信前线，**从而** 客户随时了解进度，内部协同高效。

## 子场景详解

### 子场景 A：发货与物流通知
- **角色与触发**：订单系统状态从“待发货”变为“已发货”。
- **主要流程**：
  1. 订单系统推送发货事件至 SCRM 消息网关。
  2. 企业微信机器人向客户发送物流公司、运单号、预计送达时间。
  3. 同步通知责任销售与客服，便于随时跟进。
  4. 物流状态变更持续推送，支持客户自助查询。
- **成功标准**：客户实时收到物流信息；内部人员同步；通知准确无误。
- **异常与风控**：运单号缺失或错误时不发送客户通知，并告警仓储；多次失败需人工介入。
- **指标建议**：发货通知触达率、客户查询减少率、处理延迟。

### 子场景 B：异常订单升级处理
- **角色与触发**：物流延迟、库存不足或支付失败等异常发生。
- **主要流程**：
  1. 监控服务捕获异常事件，推送到 SCRM 任务中心。
  2. 系统自动匹配责任团队（仓储/客服/财务），生成协同任务。
  3. 任务状态与处理进程实时同步至企业微信群或客户会话。
  4. 故障解决后自动发送说明与补偿方案给客户。
- **成功标准**：异常被及时发现并指派；客户获知处理进度；任务闭环记录完整。
- **异常与风控**：升级链路不可用时提供备用渠道；超时未处理自动通知主管；记录补偿日志。
- **指标建议**：异常响应时间、解决时长、客户满意度。

### 子场景 C：售后与退款进度同步
- **角色与触发**：客户发起退货、换货或售后申请。
- **主要流程**：
  1. 售后系统创建工单并同步到 SCRM，标记订单编号与原因。
  2. 客户在企微会话中随时查看审核、物流、退款进度。
  3. 客服可一键查看上下文，并邀请相关团队协同处理。
  4. 完成退款/换货后自动发送结果并邀请客户评价。
- **成功标准**：售后进度透明；客服与客户同步掌握状态；评价完成率高。
- **异常与风控**：退款失败触发二次重试和财务介入；售后超时升级；敏感信息脱敏展示。
- **指标建议**：售后进度查询次数、退款时效、评价回复率。

### 子场景 D：订单回访与复购激活
- **角色与触发**：订单完成后进入回访周期。
- **主要流程**：
  1. SCRM 根据规则调度回访机器人或销售推送感谢语与使用指南。
  2. 收集满意度与使用反馈，写回 CRM/SCRM。
  3. 判断客户兴趣度，触发复购或交叉销售建议。
  4. 数据分析对回访策略进行效果评估。
- **成功标准**：回访覆盖率高；收集到有效反馈；复购率提高。
- **异常与风控**：频次过高触发降噪；负面反馈自动转人工；回访内容需合规审核。
- **指标建议**：回访响应率、反馈采集率、复购转化率。

## 场景级测试用例示例

> 测试准备：搭建订单事件模拟器、物流 API、异常监控规则、企业微信通知模板、售后系统沙箱。

### 用例 A-1：发货通知链路验证（正向）
- **前置条件**：订单状态可模拟；客户已关联企业微信。
- **操作步骤**：
  1. 在订单系统将状态更新为“已发货”，填写运单号。
  2. 观察企业微信客户消息与内部群通知。
- **预期结果**：
  - 客户收到包含运单号与预计送达时间的消息。
  - 销售/客服收到提醒并可点击查看详情。
  - 日志记录本次推送，无重发或遗漏。

### 用例 B-1：物流异常升级（逆向）
- **前置条件**：模拟物流延迟超过 SLA；配置异常规则。
- **操作步骤**：
  1. 订单系统发出延迟事件。
  2. 查看 SCRM 任务、微信群与客户通知。
- **预期结果**：
  - SCRM 自动创建“物流延迟处理”任务，指派仓储与客服。
  - 客户收到说明与后续处理计划，客服可在任务中更新进度。
  - 任务完成后记录处理时长与结果，供报表统计。
