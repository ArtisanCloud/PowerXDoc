# 主用例说明：企微小程序商城下单（WeCom Mini Program Commerce）

## 背景概述

企业微信小程序让客户在聊天上下单、支付、查询订单成为可能。若商城与社交运营割裂，会出现下单路径长、客服无法查看订单、佣金统计困难。本主用例描述小程序商城与 SCRM 的协同：从商品展示、下单支付、订单同步到售后服务，打造社交内的交易闭环。

## 目标与价值
- **无缝下单**：客户在聊天内快速浏览、下单、支付。
- **订单同步**：销售和客服实时掌握订单状态。
- **佣金与激励**：订单自动关联发起人，计算提成。
- **运营联动**：购买行为触发后续旅程与复购策略。

## 参与角色
- **电商/产品团队**：维护小程序商品与价格。
- **销售/社群运营**：分享商品、跟进客户。
- **客服团队**：处理订单问题、售后。
- **财务/结算**：计算佣金、对账。
- **数据团队**：分析交易数据与转化。

## 主场景 User Story
> **作为** 社交销售顾问，**我希望** 客户能在企业微信小程序一键下单并将订单同步给我，**从而** 提升转化并提供及时服务。

## 子场景详解

### 子场景 A：商品卡片分享与引导
- **角色与触发**：销售在会话中推荐商品。
- **主要流程**：
  1. 销售在 SCRM 选择商品，自动生成小程序卡片。
  2. 客户点击卡片进入小程序浏览详情、规格、库存。
  3. 系统记录推荐人、会话上下文、入口渠道。
  4. 客户加购或收藏后，销售收到提醒跟进。
- **成功标准**：分享便捷；点击路径短；数据链路留痕。
- **异常与风控**：商品下架自动提示；库存不足不展示；合规审核商品信息。
- **指标建议**：卡片点击率、加购率、转化率。

### 子场景 B：下单与支付流程
- **角色与触发**：客户决定购买。
- **主要流程**：
  1. 客户选择规格、数量，填写地址。
  2. 支持企业微信支付、银行卡、第三方支付。
  3. 支付成功后生成订单号，推送给客户、销售、客服。
  4. 同步订单到电商/ERP 系统。
- **成功标准**：支付成功率高；订单同步无延迟；信息准确。
- **异常与风控**：支付失败自动重试或引导其它方式；高风险订单触发风控审核；敏感信息加密。
- **指标建议**：支付成功率、订单同步率、支付异常率。

### 子场景 C：订单状态追踪与客服协同
- **角色与触发**：订单履约过程中需要沟通。
- **主要流程**：
  1. 订单状态更新（发货、签收、退款）实时推送到会话。
  2. 客服可查看订单详情并一键响应。
  3. 客户可点击“联系专属顾问”发起咨询。
  4. 售后申请同步给 SCRM，生成工单处理。
- **成功标准**：状态透明；客服响应及时；客户满意。
- **异常与风控**：信息延迟触发告警；售后策略不一致需提示；记录所有对话。
- **指标建议**：订单咨询响应时长、售后完成率、满意度。

### 子场景 D：佣金与绩效计算
- **角色与触发**：需要计算销售提成和活动效果。
- **主要流程**：
  1. 订单关联推荐人、渠道、活动。
  2. 结算系统计算佣金与激励，推送给销售。
  3. 管理层查看排行榜、活动 ROI。
  4. 异常订单（退货）自动调整佣金。
- **成功标准**：佣金计算准确；结算及时；数据可追溯。
- **异常与风控**：异常订单拦截激励；涉嫌刷单触发调查；保留结算日志。
- **指标建议**：佣金结算时效、异常率、活动 ROI。

## 场景级测试用例示例

> 测试准备：配置小程序商品、支付沙箱、订单同步接口、佣金规则、客服工单系统。

### 用例 A-1：商品卡片下单链路（正向）
- **前置条件**：商品可售、库存充足。
- **操作步骤**：
  1. 销售分享商品卡片给客户。
  2. 客户点击卡片完成下单、支付。
- **预期结果**：
  - 客户在小程序中浏览并支付成功。
  - 销售与客服收到订单通知，含推荐人信息。
  - ERP 同步订单，佣金计算入账。

### 用例 B-1：支付失败回退（逆向）
- **前置条件**：模拟支付接口超时。
- **操作步骤**：
  1. 客户发起支付。
  2. 观察系统处理。
- **预期结果**：
  - 支付失败提示客户换用其他方式或稍后重试。
  - 订单保持“待支付”状态，销售收到提醒协助。
  - 日志记录原因，风控系统统计异常次数。
