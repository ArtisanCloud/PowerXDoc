# 主用例说明：WebAdmin Plugin Manager 运行监控

## 背景概述
随着企业在多个租户中运行大量 PowerX 插件，平台运维人员需要统一的 WebAdmin 控制台来查看插件是否在线、资源占用是否异常以及是否需要人工干预。传统的日志检索或主机级监控无法直观反馈插件维度的信息，因此需要专门的 Plugin Manager 页面聚合插件状态、性能指标与操作入口，帮助运营、运维、场景团队快速诊断问题并触发调度动作。

## 目标与价值
- **统一可视化**：在单页中总览所有插件实例的健康度、启动状态、版本信息。
- **指标可观测**：实时展示 CPU、内存、网络吞吐、消息队列积压、最近任务成功率等关键指标。
- **一键运维动作**：提供启停、重启、滚动升级、限流、日志下载等常用操作，并记录审计日志。
- **多租户安全隔离**：按照租户与部署节点划分视图，确保运维操作受 ACL 控制并可追溯。

## 参与角色
- **企业运维 / SRE**：监控插件运行状况、处理告警、执行运维操作。
- **运营/场景负责人**：关注特定业务插件的执行任务数与成功率，决定是否扩容或调整调度策略。
- **安全合规人员**：查看敏感插件的访问记录、版本签名、异常行为。
- **系统服务**：Telemetry 指标服务、日志服务、通知中心、ACL 与审计服务。

## 主场景 User Story
> **作为** 企业运维人员，**我希望** 在 WebAdmin → Plugin Manager 页面即可实时查看每个插件实例的状态并执行启停/重启等操作，**从而** 快速处理异常、保障多租户环境的插件稳定运行。

## 子场景详解

### 子场景 A：全局总览与筛选
- **触发**：运维登录 WebAdmin，进入 Plugin Manager 以巡检所有插件。
- **流程**：
  1. 页面默认展示分组卡片：按租户、业务域、部署节点整理插件列表。
  2. 顶部提供筛选条件（租户、插件类型、状态、版本、标签）。
  3. 每张卡片显示：运行状态（Running/Stopped/Degraded）、版本号、实例数量、最近一次部署时间。
  4. 颜色或标签提示异常（CPU > 阈值、连续失败、License 即将到期）。
- **成功标准**：筛选与排序在 1 秒内返回；卡片与后台状态实时同步（<10s 延迟）；异常标记点击后可跳转详情。

### 子场景 B：指标监控与告警
- **触发**：运维希望排查某个插件耗资源过高的原因。
- **流程**：
  1. 点击插件卡片进入详情抽屉，展示时间序列曲线：CPU%、内存(MB)、网络上下行、消息堆积、任务成功率等。
  2. 支持选择时间范围（最近 15 分钟 / 1 小时 / 24 小时）；支持导出 CSV/JSON。
  3. 页面与 Telemetry 服务交互，若指标超过阈值，自动高亮并关联到通知中心的告警记录。
  4. 运维可在此处设置或调整告警阈值、告警接收人。
- **成功标准**：图表加载时间 <2 秒；超过阈值自动触发 Webhook/邮件/IM 告警；所有配置变更记录审计日志。

### 子场景 C：运维操作与审计
- **触发**：插件出现异常需要重启或扩缩容。
- **流程**：
  1. 在详情面板点击“重启/停用/升级/限流”按钮，系统弹出确认对话框并显示受影响实例数。
  2. 操作需要具备相应 ACL 权限；若为生产租户，可要求双人审批或输入二次验证。
  3. 执行后实时更新卡片状态，并显示操作结果（成功/失败/队列中）。
  4. 所有操作写入审计日志，可导出 CSV，供安全团队复核。
- **成功标准**：操作请求在 5 秒内发起；状态实时同步；失败时返回明确错误并提供重试建议。

### 子场景 D：日志与任务追踪
- **触发**：运营人员需要定位最近一次 RPA Flow 执行失败的原因。
- **流程**：
  1. 在插件详情中切换到“任务/日志”页签，查看最近 100 条执行记录及成功率。
  2. 支持按任务类型、触发来源（定时/Agent 调度）、租户用户过滤，并可直接跳至 Workflow Trace。
  3. 点击日志行可展开原始日志片段或下载完整日志；可直接分享到调查工单。
- **成功标准**：日志检索延迟 <3 秒；下载链接带鉴权签名；Workflow Trace 链接跳转正确。

## 功能边界
- 不涉及插件代码构建、发布与签名流程（由“插件发布与上架”“插件签名与验证”主用例覆盖）。
- 不处理宿主层面的节点自动伸缩与调度策略，仅聚焦插件视角的监控与操作。
- 不提供细粒度任务设计功能，该能力由 Workflow、RPA 等场景负责。

## 依赖与接口
- **Telemetry & Metrics**：提供实时指标、时间序列查询接口。
- **日志服务**：支持按插件、租户、时间范围检索并下载日志。
- **操作编排 API**：如 `/plugins/{id}/restart`、`/scale`、`/throttle`。
- **权限与审计**：ACL 系统授权页面操作，审计服务记录每个动作。
- **通知中心**：订阅并推送告警，支持 Webhook/Email/IM。

## 验收要点
1. Plugin Manager 页面需在 2 秒内完成首屏渲染，并按租户/状态筛选返回结果。
2. 指标、日志与操作结果均需与后台实时同步，延迟不得超过 10 秒。
3. 运维操作（启停、重启、限流）必须具备权限校验与二次确认，并生成可追溯的审计记录。
4. 告警阈值、通知通道等配置变更需记录来源、操作者、时间戳，支持回滚。
5. 所有导出（日志、指标）需具备鉴权签名，并在 24 小时内过期。

## 测试用例示例
- **正向**：在沙箱环境部署 3 个插件实例，确认 Plugin Manager 能正确显示状态，并在 CPU 超阈值时触发告警；执行“重启”操作后 10 秒内状态恢复并记录审计日志。
- **逆向**：未授权用户尝试停用生产插件，被 ACL 拒绝并提示申请权限；Metrics 服务短暂不可用时前端显示降级提示且提供重试按钮。
