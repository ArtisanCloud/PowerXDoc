# 主用例说明：统一 Worker 封装与双模式任务执行

## 背景概述
PowerX 需要为插件提供一致的异步任务执行体验，无论运行于本地独立模式还是宿主托管模式。面向长耗时任务（如文件下载、转码、数据同步、模型推理等），业务 Handler（可调用外部二进制或服务，支持进度/错误回写、取消/超时处理）希望一次编写、两端复用；调度、并发、重试、观测、降级等差异由 PowerXPlugin framework 的统一 Worker 封装承担。本主用例聚焦“统一 Worker 封装与双模式任务执行”，描述如何通过一致接口、可配置策略和可观测性，支撑插件任务在双运行模式间无感切换。

## 目标与价值
- **接口一致**：对外提供统一的 Worker 接口/调度器（提交/取消/查询/回写），业务与前端无需区分运行模式。
- **双模式复用**：同一 Handler 逻辑可在 standalone（本地队列+goroutine 池）与宿主模式（底座任务分发）间切换，无需分叉代码。
- **脚手架开箱支持**：PowerXPlugin 生成的插件工程自带 Worker 启动模板与 standalone 模式配置，本地即可跑通异步任务链路。
- **可配置可靠性**：并发、队列长度、超时、重试/退避等策略均可配置，默认值一致，支持任务幂等。
- **一致观测与降级**：两种模式都具备进度/状态回写、日志与告警；宿主不可用时可回退本地或显式失败。

## 参与角色
- **插件开发者/责任人**：实现业务 Handler，配置任务策略与回写格式。
- **PowerXPlugin Worker 封装层**：暴露统一接口，负责任务队列、并发、超时、取消、重试、回写与观测。
- **本地队列与 goroutine 池**：standalone 模式下执行任务并管理资源。
- **宿主任务分发服务**：宿主模式下负责任务注册、提交、取消与执行监控。
- **运维/平台管理员**：设置全局/租户级策略，查看任务执行与告警。
- **前端/控制台**：查询任务状态、进度与日志，无需关注运行模式。

## 插件脚手架（PowerXPlugin）侧支持
- PowerXPlugin 脚手架生成的插件工程默认内置 Worker 模块与配置模板，支持 standalone 与宿主双模式切换，Handler 注册与回写接口保持一致。
- 提供 standalone 启动入口（如独立二进制或等效 CLI 脚本），复用同一 Handler 代码，依赖本地队列 + goroutine 池执行异步任务。
- 启动参数或配置项可一键切换运行模式（例如 runtimeMode/worker.local.enabled 等开关），无需修改业务 Handler。
- 脚手架包含示例 Handler、进度回写与日志模板，便于在无宿主环境下完成自验与演示。

## 主场景 User Story
> **作为** 插件开发者/运维负责人，**我希望** 通过统一的 Worker 接口提交、取消并观测插件任务，在 standalone 或宿主模式下都能获得一致的并发控制、超时/重试、进度回写与告警体验，**从而** 降低接入成本并保障长耗时任务的可靠执行。

## 子场景详解

### 子场景 A：standalone 模式本地队列 + goroutine 池执行任务
- **角色与触发**：插件在独立运行时提交长耗时任务（如文件下载/转码/数据同步），由本地队列与 goroutine 池调度。
- **主要流程**：
  1. 使用 PowerXPlugin 脚手架提供的 standalone 启动入口（加载本地队列、goroutine 池与默认策略），完成 Handler 注册。
  2. 业务通过统一接口提交任务，附带并发、队列长度、超时、重试策略（可使用默认值）。
  3. Worker 封装将任务入队，依据池容量分配 goroutine 执行 Handler（可能调用外部下载器/转码器/ETL 工具）。
  4. Handler 周期性回写进度与状态至任务表/状态机；超时或失败按策略重试。
  5. 日志与错误记录写入本地观测（文件/stdout），可选推送告警。
- **成功标准**：任务按策略执行并可查询进度；超时/失败触发重试；队列与并发受控；日志可用于追踪。
- **异常与风控**：队列溢出时拒绝并返回可诊断错误；重试达到上限需告警；防止 goroutine 泄漏。
- **指标建议**：队列深度、并发占用、任务成功率、重试次数、平均完成时长。

### 子场景 B：宿主模式透传到底座任务分发
- **角色与触发**：插件运行在宿主中，需通过同一接口注册 Handler 并提交/取消任务，由底座承担队列、并发与监控。
- **主要流程**：
  1. 插件在初始化时向 Worker 封装注册任务 Handler（业务代码与 standalone 复用）。
  2. 任务提交通过封装层透传到底座任务分发服务，包含超时、重试、幂等键等策略。
  3. 底座负责执行、状态/进度回写；封装层将回写同步给业务/前端。
  4. 告警与监控继承宿主能力（告警平台、仪表盘），并可回传插件侧日志上下文。
- **成功标准**：接口契约与 standalone 一致；任务状态可查；取消/重试生效；宿主监控可用。
- **异常与风控**：注册/提交失败需返回可恢复错误；底座异常时支持降级策略（回退本地或显式失败）；需鉴权防止越权调用。
- **指标建议**：宿主接入成功率、任务投递/回写延迟、跨模式行为一致性缺陷数。

### 子场景 C：统一取消/超时与进程终止
- **角色与触发**：用户或系统请求取消/超时终止任务（如终止外部下载/转码进程）。
- **主要流程**：
  1. 通过统一接口提交取消/终止请求，封装层在两种模式下均需处理。
  2. standalone：封装层向 goroutine 发送取消信号并终止子进程，更新状态为取消。
  3. 宿主：封装层将取消指令透传到底座，底座终止执行并回写状态；封装层确保幂等。
  4. 取消结果/失败原因回写任务表，前端保持一致呈现。
- **成功标准**：取消在可配置超时时间内完成；子进程被终止；状态回写一致；无僵尸任务。
- **异常与风控**：取消失败需升级告警；确保重入幂等；防止误取消可配置确认。
- **指标建议**：取消成功率、取消耗时、超时终止次数。

### 子场景 D：观测、告警与降级策略
- **角色与触发**：运维需要在两种模式下获得观测与告警；宿主不可用时需降级。
- **主要流程**：
  1. standalone：任务执行日志/错误记录本地，暴露基础指标（成功率、队列、耗时）并可选推送告警。
  2. 宿主：沿用底座监控/告警，封装层补充插件侧上下文（参数、子进程日志）。
  3. 当宿主不可用或连接失败时，根据配置选择回退本地执行或显式报错拒绝。
  4. 前端/运维界面保持统一视图，标识当前运行模式与降级状态。
- **成功标准**：两种模式都有可用观测；降级策略按配置执行；告警链路可靠。
- **异常与风控**：防止告警风暴；降级需记录审计；回退本地需评估资源与安全边界。
- **指标建议**：观测覆盖率、告警送达率、降级触发次数与成功率。

### 子场景 E：PowerX Admin 任务看板
- **角色与触发**：平台管理员或运维在 PowerX Admin 中查看各插件的异步任务使用、状态与日志。
- **主要流程**：
  1. 管理员打开任务看板，按租户/插件/运行模式（standalone/宿主）筛选任务。
  2. 看板展示队列深度、并发使用、成功/失败/重试/取消状态占比、近期耗时分布与告警。
  3. 任务详情页可查看进度、日志片段、回写上下文与宿主/本地执行节点信息。
  4. 支持从看板发起取消/重试（需权限校验与审计）、下载日志或跳转至宿主监控视图。
- **成功标准**：看板数据延迟可控（如 <1 分钟）；筛选与分页可用；操作受 ACL 控制并写审计；跨模式字段一致。
- **异常与风控**：监控数据缺失需标记并提示采集状态；防止误操作（确认/权限）；日志访问遵循租户隔离与敏感脱敏。
- **指标建议**：看板加载时延、查询成功率、日志读取成功率、跨模式数据一致性。

## 功能边界 & 非目标场景
- 不覆盖复杂 BPM/长流程建模；仅聚焦插件级异步任务调度与执行。
- 不讨论业务 Handler 内部业务逻辑实现，仅定义接口、策略与运行模式切换。
- 不涵盖宿主层的底层资源调度实现细节（如 Kubernetes 调度），仅描述接口契约与行为。

## 依赖与接口
- **PowerXPlugin 脚手架/启动框架**：生成插件工程时提供 standalone/宿主双模式启动入口、默认配置与示例 Handler，复用统一 Worker 接口。
- **PowerXPlugin Worker 接口**：提交/取消/查询任务，注册 Handler，状态/进度回写格式。
- **本地队列与 goroutine 池**：提供任务排队、并发、超时与重试能力。
- **宿主任务分发服务**：任务注册、调度、监控、告警与回写。
- **进程管理与信号机制**：用于终止子进程（如外部下载/转码/ETL 工具）与处理超时/取消。
- **配置中心**：存储并发、队列、超时、重试、降级策略的默认与覆盖值。
- **观测与告警**：standalone 的日志/指标采集与告警；宿主监控/告警链路；任务看板查询接口。
- **权限与审计**：校验跨模式操作权限，记录任务提交、取消与降级决策。

## 验收要点
1. 统一接口在 standalone/宿主模式均可提交、取消、查询任务，状态/进度回写格式一致。
2. 并发、队列长度、超时、重试策略可配置且默认值一致；重试支持退避与幂等键。
3. 取消/超时可终止子进程（如外部下载/转码/ETL 工具），两种模式下均能在 SLA 内回写结果。
4. 观测与告警可用：standalone 提供基础日志/指标，宿主复用底座监控并附加插件上下文。
5. 宿主不可用时的降级策略（回退本地或显式失败）可配置且有审计记录。
6. PowerX Admin 任务看板可按租户/插件/模式查询任务，展示指标与日志摘要，支持受控的取消/重试并留存审计。
7. PowerXPlugin 脚手架生成的插件工程可直接以 standalone 模式启动 Worker（本地队列+池），无需额外改造即可跑通异步任务与回写。

## 场景级测试用例示例

> 测试准备：准备同一 Handler（例如文件下载/转码示例），配置统一 Worker 接口；为 standalone 配置本地队列与 goroutine 池，为宿主配置任务分发接入；设置默认并发=5、队列长度=100、超时=5 分钟、重试=3 次退避；开启进度回写与日志采集。

### 用例 A-1：standalone 模式任务成功（正向）
- **前置条件**：standalone 模式启用；使用默认策略。
- **操作步骤**：
  1. 通过统一接口提交示例任务。
  2. 观察进度回写与日志。
- **预期结果**：
  - 任务入队并在池容量内执行，进度按期回写。
  - 完成后状态=成功，记录耗时与任务输出。
  - 队列与并发指标可查询。

### 用例 A-2：standalone 队列溢出（逆向）
- **前置条件**：将队列长度配置为 1，连续提交 3 个任务。
- **操作步骤**：
  1. 提交第 1、2、3 个任务。
- **预期结果**：
  - 第 1 个任务执行，第 2 个排队，第 3 个被拒绝并返回可诊断错误。
  - 日志记录拒绝原因，触发告警。

### 用例 B-1：宿主模式任务执行与回写（正向）
- **前置条件**：宿主任务分发可用，已注册 Handler。
- **操作步骤**：
  1. 通过统一接口提交任务（含超时/重试策略）。
  2. 观察宿主回写的进度与最终状态。
- **预期结果**：
  - 任务成功投递至宿主并执行，进度/状态回写与 standalone 格式一致。
  - 告警/监控可在宿主控制台查看。

### 用例 C-1：取消任务终止子进程（正向）
- **前置条件**：任务执行中（外部进程仍在运行）。
- **操作步骤**：
  1. 调用取消接口。
- **预期结果**：
  - standalone：子进程被终止，状态回写为取消。
  - 宿主：取消指令透传并终止执行，状态一致。
  - 无残留僵尸进程，审计记录完整。

### 用例 D-1：宿主不可用触发降级（逆向）
- **前置条件**：模拟宿主任务分发不可达，降级策略=回退本地。
- **操作步骤**：
  1. 提交任务。
- **预期结果**：
  - 封装层检测宿主不可用后回退到本地队列执行并记录降级事件。
  - 进度/状态回写可见，告警提示降级模式。
  - 审计记录包含降级原因与执行路径。
