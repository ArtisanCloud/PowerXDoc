# 主用例说明：智能体模型与平台接入

## 背景概述
PowerX 作为企业级智能体底座，需要同时管理多种基础模型（LLM、VLM、TTS、Embeddings），并对接 Coze、n8n 等智能体工作流平台。业务团队通常希望在一个租户中自由选择模型、切换推理策略或引入外部平台，但如果缺乏统一的 Provider 注册、密钥治理与健康监控，常见问题包括：模型密钥泄露、配额耗尽未告警、策略路由不可控、外部平台回调失效以及难以溯源的成本暴涨。该主用例聚焦“模型与智能体平台接入”的全链路治理，覆盖 provider 注册、策略路由、平台连接器以及配额/成本与审计能力，确保任何智能体任务都能基于可控、可观测的模型与平台能力运行。

## 目标与价值
- **统一接入**：为 LLM/VLM/TTS/Embeddings 以及外部智能体平台提供一致的注册、配置与验证流程。
- **动态路由**：根据任务类型、延迟、成本、租户偏好在多模型、多平台之间自动路由并支持 fallback。
- **治理可观**：集中管理密钥、配额、成本和健康信号，及时告警并可一键降级或停用异常 provider。
- **扩展友好**：对接 Coze、n8n 等平台时复用身份、审计与限流策略，降低多平台协同的运维成本。

## 参与角色
- **Provider 管理员（Platform Ops）**：负责在 `backend/config/agents/**` 中注册 provider、校验参数、管理密钥与租户映射。
- **模型路由服务（Multi-Model Router）**：维护能力标签、策略权重、A/B 试验与 fallback 逻辑。
- **平台连接器团队（Plugin Guild）**：实现 Coze、n8n 等外部平台的连接器、回调签名与上下文映射。
- **成本与配额治理（Ops Reliability Center）**：监控用量、成本、异常告警并触发降级或停用策略。
- **主 Agent / Planner**：在任务规划阶段查询模型/平台能力、接收健康信号、选择最佳 provider。

## 主场景 User Story
> **作为** 智能体平台的技术负责人，**我希望** 能在一个统一的“模型与平台接入中心”管理所有基础模型和外部智能体平台，**从而** 在不同租户和任务下快速选择合适的模型/平台、控制成本并满足合规要求。

## 子场景详解

### 子场景 A：基础模型 Provider 引入与治理
- **角色与触发**：Platform Ops 需要上线新的 LLM/VLM/TTS/Embeddings provider。
- **主要流程**：
  1. 在 `backend/config/agents/providers/*.yaml` 中登记 provider，包含区域、能力标签、调用入口、配额策略等。
  2. 将密钥托管至 Vault/Secret Manager，并与租户、环境、Feature Flag 绑定。
  3. 运行自动化验证脚本（健康 ping、延迟测试、审计写入），通过后标记为“可用”。
  4. 发布到租户级配置中心，允许部分租户灰度启用。
- **成功标准**：24 小时内完成注册验证；密钥全部托管且可轮换；健康检查通过率 ≥99%。
- **异常与风控**：校验失败自动回滚；未通过合规审计禁止启用；密钥即将过期提前告警。
- **指标建议**：接入时长、健康检查成功率、密钥轮换覆盖率。

### 子场景 B：多模型路由与策略编排
- **角色与触发**：Planner 需要根据任务上下文自动选择模型。
- **主要流程**：
  1. 多模型路由服务读取任务标签（行业、语言、敏感级别、期望延迟）。
  2. 根据策略权重、成本、健康分数挑选主模型与备用模型；可运行 A/B 或灰度策略。
  3. 输出路由决策与 Trace ID，供执行层调用；同时记录成本估算与风险标签。
  4. 当主模型失败时自动触发 fallback 或降级策略，并回写审计。
- **成功标准**：策略命中率 ≥90%；fallback 成功率 ≥95%；决策耗时 <200ms。
- **异常与风控**：策略回滚需秒级生效；检测到异常成本或错误率飙升时自动切换至安全模式。
- **指标建议**：命中率、fallback 次数、策略回滚耗时、成本/延迟波动。

### 子场景 C：外部智能体平台接入（Coze、n8n 等）
- **角色与触发**：业务需要使用第三方工作流平台完成复杂自动化。
- **主要流程**：
  1. 通过连接器创建平台实例，完成 OAuth/Token 管理与权限配置。
  2. 映射 PowerX 的租户、用户、上下文到平台要求的格式，配置回调/Webhook 签名。
  3. 主 Agent 调用连接器触发工作流，连接器负责状态同步、重试与异常翻译。
  4. 结果回传后写入 PowerX 的任务看板与审计记录，供后续闭环验证。
- **成功标准**：回调延迟 <3s；签名校验通过率 100%；异常可在 10 分钟内回放定位。
- **异常与风控**：当平台不可用时自动降级到本地流程或人工审批；跨租户调用严格隔离。
- **指标建议**：平台调用成功率、回调延迟、签名失败次数、降级触发总数。

### 子场景 D：成本、配额与可观测治理
- **角色与触发**：Ops 需要实时掌握模型/平台使用情况并控制成本。
- **主要流程**：
  1. 采集每次调用的 Token 数、时长、成本计算并写入 Cost Warehouse。
  2. 与租户/项目配额进行对比，超阈值触发限流、降级或停用策略，并通知负责人。
  3. 将健康分数、延迟、错误率、成本等指标推送到 Grafana/Datadog。
  4. 定期生成报表（租户、模型、平台维度）并输出审计记录。
- **成功标准**：成本数据延迟 <1 分钟；超配额告警 5 分钟内触达；限流/停用操作审计 100% 完整。
- **异常与风控**：计费接口异常时自动回退到缓存策略；防止告警风暴（聚合/抑制）。
- **指标建议**：成本超阈次数、限流触发数、告警确认时间、审计缺口数。

## 功能边界 & 非目标场景
- 不覆盖模型训练、微调或评估体系，相关内容由 MLOps 场景负责。
- 不负责业务插件逻辑，本文仅管理模型/provider 与平台层能力。
- 第三方平台内部审批/运维流程不在范围内，只保证标准接口互通。
- 与主任务执行场景的联动：本场景提供模型/平台能力与健康信号，执行层仅消费 API。

## 依赖与接口
- **配置与注册**：`backend/config/agents/providers/*.yaml`、`backend/config/agents/routing/*.yaml`。
- **安全治理**：Vault/Secret Manager、Feature Flag 服务、Quota/Cost Service。
- **监控与审计**：`agent.provider.*` 指标、Grafana Model Hub、审计流 `agent.provider.audit`。
- **外部平台**：Coze、n8n 官方 API、Webhook 网关、回调签名库。

## 验收要点
1. 新增 provider 可在 24 小时内完成注册、密钥托管、健康验证并灰度上线。
2. 多模型路由能根据策略页面实时调整权重并在秒级生效，支持 fallback 与安全模式。
3. 外部平台调用全程可追踪，回调签名、一致性校验与降级策略可验证。
4. 成本/配额监控可在 5 分钟内告警，限流或停用操作具备审计与回放能力。
5. 与“智能体任务执行”“ReAct 智能体编排”等场景共享能力图谱与健康信号，实现链路协同。

## 场景级测试用例示例

> 沙箱：`tenant-model-hub-lab`，开启 `model-provider-registry`、`multi-model-router`、`agent-platform-connectors`，并接入 openAI、Wenxin、Custom-TTS、Coze、n8n。

### 用例 A-1：LLM Provider 接入（正向）
- **前置条件**：准备新 provider 密钥与配置文件。
- **操作**：登记 provider、触发验证脚本。
- **预期**：验证全部通过，状态变为“可用”，租户配置中心可选择该模型。

### 用例 A-2：密钥轮换失败（逆向）
- **操作**：模拟旧密钥失效。
- **预期**：调用被阻断并触发告警，要求重新校验密钥。

### 用例 B-1：多模型路由命中（正向）
- **操作**：Planner 提交高复杂度任务。
- **预期**：命中指定策略，记录主模型、备用模型与成本估算。

### 用例 B-2：fallback 生效（逆向）
- **操作**：主模型强制返回错误。
- **预期**：自动切换备用模型并记录审计，任务继续成功。

### 用例 C-1：Coze 工作流调用（正向）
- **操作**：通过连接器触发 Coze 工作流。
- **预期**：上下文映射成功，回调签名通过，结果同步到任务看板。

### 用例 C-2：n8n 回调异常（逆向）
- **操作**：模拟回调签名错误。
- **预期**：请求被拒绝并触发告警，可在控制台重试或切换备用。

### 用例 D-1：成本告警与降级（正向）
- **操作**：对高成本模型进行压测，触达预算阈值。
- **预期**：5 分钟内告警并自动切换为低成本策略，审计记录完整。
