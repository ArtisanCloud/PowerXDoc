# 页面 12｜B6 第二阶段：MCP（远程连接与共享上下文）

## 页面目标
讲清 Agent 生长的第二步：从“本地能做”进化到“跨系统可协同”。

## 先讲一个场景（开场 20 秒）
- `当 Agent 不只要查本地数据，还要连 CRM、广告平台、知识库时，单机 Tool Call 不够了，这时就需要 MCP。`

## 页面展示（PPT 怎么做）

### 版式
- 顶部 20%：标题区
  - 主标题：`B6 第二阶段：MCP`
  - 副标题：`把“单机执行”升级为“远程协同”`
- 中部 55%：连接拓扑图
  - 左：`Agent`
  - 中：`MCP 接入层`
  - 右：`CRM / 广告平台 / BI / 知识库`
- 底部 25%：阶段价值 + 阶段边界
  - 价值：`统一接入、跨 Agent 复用、减少重复集成`
  - 边界：`只连通还不够，还缺“可复用工作方法”`

### 图上文案（可直接粘贴）
- MCP 是什么
  - `模型上下文与工具接入的统一协议层`
  - `让 Agent 用统一方式访问外部系统`
- 在 Agent 生长中的作用
  - `把“本地动作”扩展为“跨系统动作”`
  - `把“单 Agent 集成”升级为“多 Agent 共享集成”`
- 典型价值
  - `接入标准化：减少重复开发`
  - `上下文共享：同一事实源被多个 Agent 复用`
  - `运维集中化：连接治理更可控`
- 典型限制
  - `有连接不等于有方法`
  - `仍需把业务 SOP 固化，避免每次临场拼接`
- 结论条
  - `MCP 解决“连到哪”，下一步要解决“怎么稳定复用”。`

### 动效顺序（建议）
1. 先出连接拓扑（Agent -> MCP -> 外部系统）。
2. 再出现“作用”和“价值”。
3. 最后出现“限制”与下页过渡：为什么需要 Skill。

## 讲述脚本（怎么讲）

### 时间分配（本页 3 分钟）
- 第 1 分钟：讲为什么出现 MCP
  - 重点句：系统越多，点对点集成越不可持续。
- 第 2 分钟：讲 MCP 的核心价值
  - 重点句：一次接入，多处复用，降低集成摩擦。
- 第 3 分钟：讲阶段边界
  - 重点句：连接打通后，真正差距变成“有没有可复用方法论”。

### 讲师话术（可直接用）
- 开场：`MCP 不是模型能力升级，而是工程连接升级。`
- 过渡：`它让 Agent 不再困在本地环境，而能进入企业系统网络。`
- 收口：`下一页 Skill，解决“同样连接条件下，谁能稳定跑出结果”。`

### 课堂互动（建议）
- 互动题：`你们当前最多要打通哪三类系统？`
- 追问：`这些系统今天是标准接入，还是每次临时开发？`
