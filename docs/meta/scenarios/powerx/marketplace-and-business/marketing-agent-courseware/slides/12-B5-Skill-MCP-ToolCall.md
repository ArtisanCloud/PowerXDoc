# 页面 12｜B5 第一阶段：Tool Calling（本地执行起点）

## 页面目标
讲清 Agent 生长的第一步：从“只会回答”进化到“会调用本地工具完成动作”。

## 先讲一个场景（开场 20 秒）
- `最早我们让 Agent 先调用本地脚本：查报表、生成名单、导出任务单。这一步就把“提建议”变成了“真执行”。`

## 页面展示（PPT 怎么做）

### 版式
- 顶部 20%：标题区
  - 主标题：`B5 第一阶段：Tool Calling`
  - 副标题：`让 Agent 先学会“调用工具做事”`
- 中部 55%：三段流程图
  - `模型判断 -> 发起 Tool Call -> 本地执行并回填结果`
- 底部 25%：阶段价值 + 阶段边界
  - 价值：`把“建议器”升级为“执行器”`
  - 边界：`能力受限于本机工具，跨系统协同弱`

### 图上文案（可直接粘贴）
- Tool Calling 是什么
  - `模型按结构化参数调用工具（不是纯文本指令）`
  - `执行结果返回给模型，继续下一步决策`
- 在 Agent 生长中的作用
  - `第一次具备“行动能力”`
  - `能把重复动作自动化（查数、筛选、导出、通知）`
- 典型价值
  - `响应更快：分钟级执行固定动作`
  - `更稳定：同一动作可重复、可审计`
- 典型限制
  - `依赖本地环境，难跨团队共享`
  - `工具越多，维护复杂度越高`
- 结论条
  - `Tool Calling 解决“能不能做”，但还没解决“跨系统协作”。`

### 动效顺序（建议）
1. 先出现三段流程：判断 -> 调用 -> 回填。
2. 再出现“作用”和“限制”两组要点。
3. 最后收口到下一页：为什么需要 MCP。

## 讲述脚本（怎么讲）

### 时间分配（本页 3 分钟）
- 第 1 分钟：讲机制
  - 重点句：Tool Call 是 Agent 从语言系统进化为行动系统的起点。
- 第 2 分钟：讲价值
  - 重点句：最先落地的是高频重复动作，不是复杂策略。
- 第 3 分钟：讲边界
  - 重点句：一旦需要跨系统、跨团队协作，就会遇到本地集成瓶颈。

### 讲师话术（可直接用）
- 开场：`Agent 最早不是先“变聪明”，而是先“能动手”。`
- 过渡：`Tool Calling 让它能执行动作，但动作范围仍然局部。`
- 收口：`下一页进入 MCP，解决跨系统连接和共享的问题。`

### 课堂互动（建议）
- 互动题：`你们团队现在有哪些动作已经可以交给 Tool Call 自动执行？`
- 追问：`哪些动作仍然卡在“系统打不通”？`

### 反例提醒（1 句话）
- `如果 Tool Call 只连本地脚本而不做治理，后期会变成“自动化烟囱”。`
