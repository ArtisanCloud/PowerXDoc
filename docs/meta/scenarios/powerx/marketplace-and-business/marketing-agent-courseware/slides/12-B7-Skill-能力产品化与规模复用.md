# 页面 12｜B7 第三阶段：Skill（能力产品化与规模复用）

## 页面目标
讲清 Agent 生长的第三步：从“能连系统”进化到“可复用、可治理、可规模交付”。

## 先讲一个场景（开场 20 秒）
- `同样连了 MCP，有的团队每次都临场发挥，有的团队可以稳定复制成功做法。差异就在 Skill。`

## 页面展示（PPT 怎么做）

### 版式
- 顶部 20%：标题区
  - 主标题：`B7 第三阶段：Skill`
  - 副标题：`把高手经验变成可复用能力单元`
- 中部 55%：能力产品化图
  - 左：`业务方法（SOP/策略）`
  - 中：`Skill 封装（输入/步骤/约束/输出）`
  - 右：`多场景复用（跨团队、跨 Agent）`
- 底部 25%：阶段价值 + 治理要点
  - 价值：`复用率提升、交付一致性提升、上线更快`
  - 治理：`版本管理、评估标准、灰度发布、回滚机制`

### 图上文案（可直接粘贴）
- Skill 是什么
  - `把可验证的方法论封装为可执行能力模块`
  - `不是 prompt 片段，而是带约束和输出标准的能力包`
- 在 Agent 生长中的作用
  - `把“个人经验”变成“组织资产”`
  - `把“临场发挥”变成“稳定交付”`
- 典型价值
  - `复用：同一 Skill 多场景复用`
  - `一致：输出质量可预测`
  - `迭代：版本化升级，持续优化`
- 治理要点
  - `每个 Skill 有负责人、版本号、验收指标`
  - `上线走灰度，异常可一键回滚`
  - `效果按业务指标复盘（转化率、ROI、响应时长）`
- 结论条
  - `Tool Calling 让 Agent 会做，MCP 让 Agent 能连，Skill 让 Agent 可规模化。`

### 动效顺序（建议）
1. 先出“方法 -> 封装 -> 复用”主链路。
2. 再出现“价值”三点（复用/一致/迭代）。
3. 最后出现“治理要点”和收口结论。

## 讲述脚本（怎么讲）

### 时间分配（本页 3 分钟）
- 第 1 分钟：讲为什么 Skill 火
  - 重点句：企业真正稀缺的不是模型，而是可复制的方法资产。
- 第 2 分钟：讲 Skill 在工程中的位置
  - 重点句：Skill 建在 Tool Calling 和 MCP 之上，决定产出稳定性。
- 第 3 分钟：讲治理与规模化
  - 重点句：没有版本和评估，Skill 很快会失效；有治理，才能规模复制。

### 讲师话术（可直接用）
- 开场：`最近 Skill 很火，本质是“能力产品化”。`
- 过渡：`同样的模型和连接条件，真正拉开差距的是可复用方法库。`
- 收口：`到这一步，Agent 才从“工具能力”进入“组织能力”。`

### 课堂互动（建议）
- 互动题：`你们团队最值得先封装成 Skill 的一个流程是什么？`
- 追问：`这个 Skill 的验收指标准备怎么定义？`
