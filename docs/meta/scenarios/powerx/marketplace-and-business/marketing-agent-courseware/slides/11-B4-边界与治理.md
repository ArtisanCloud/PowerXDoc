讲清四件事：`为什么 OpenClaw 火`、`它能做什么`、`2C 与 2B 的本质差异`、`2B 如何做严谨且省 token 的方案`。

### 图上文案（可直接粘贴）
- 为什么火
  - `开源可改，社区迭代快`
  - `1-2 周可做出可演示 PoC`
  - `试错成本低，团队容易快速看到价值`
- 它能做到什么
  - `多步骤任务编排（感知 -> 决策 -> 执行）`
  - `可调用外部工具与业务系统`
  - `把“人盯流程”变成“系统跑闭环”`
- 转折：2C vs 2B
  - `2C：个人使用，情绪价值拉满，主动聊天体验优先`
  - `2B：企业使用，任务准确、流程闭环、结果可追责优先`
  - `2B 落地必须专业人员定制开发（系统集成、权限模型、审批链路）`
- 2B 严谨且省 token 方案
  - `模型路由：小模型默认，大模型只处理高复杂度步骤`
  - `缓存优先：命中历史答案/策略，不重复推理`
  - `RAG 压缩：先检索再摘要，严格限制上下文长度`
  - `工具优先：能查库就不让模型猜`
  - `成本闸门：单任务 token 上限 + 超限降级 + 人工兜底`
- 金句（放底部）
  - `2C 拼情绪价值，2B 拼专业定制与工程治理。`

## 讲述脚本（怎么讲）

### 时间分配（本页 3 分钟）
- 第 1 分钟：讲热度与能力
  - 重点句：OpenClaw 火是因为它把智能体试点门槛大幅降低。
- 第 2 分钟：讲 2C/2B 转折
  - 重点句：2C 重体验，2B 重责任，二者不是一套上线逻辑。
- 第 3 分钟：讲 2B 落地方法
  - 重点句：2B 要靠专业定制开发，把安全与 token 成本一起治理。

### 讲师话术（可直接用）
- 开场：`OpenClaw 很火，这是事实；但对 2B 而言，能跑只是第一步。`
- 过渡：`2C 可以先追求“好聊”，2B 必须先保证“可控、可审、可回滚”。`
- 收口：`建议路径是“开源 PoC 快验证 + 专业定制做生产”。`
