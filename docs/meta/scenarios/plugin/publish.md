
# 🧩 PowerX Plugin 插件开发与分发用例设计说明

## 一、概述

PowerX Plugin 是 PowerX 平台的插件开发与分发体系。
开发者基于 **PowerXPlugin 仓（PLG）** 提供的 SDK 与接口，可以开发独立插件应用（例如 `PowerXPluginNote`）。
开发完成后，通过各自的 CLI 工具（`px-plugin`、`px-admin`、`px-market`）即可实现插件的构建、调试、打包与发布，最终部署到 PowerX 系统。

---

## 二、用例总览

插件的开发与分发共分为三个核心用例：

1. **本地调试模式** — 开发者在本地构建插件，并直接在 PowerX Admin 环境中加载测试。
2. **离线打包上传模式** — 将插件打包为压缩包，通过 Marketplace 页面手动上传。
3. **在线发布模式** — 通过命令行或 Marketplace 管理页面直接发布至线上市场。

这三种方式覆盖了开发、内网部署及正式生态发布的全链路场景。

---

## 三、子用例说明

### 1️⃣ 本地调试模式

**目的**：
便于开发者在本地环境快速验证插件功能与接口。

**流程：**

1. 在 PowerXPlugin 仓内使用 `px-plugin` 构建插件，生成编译输出目录（如 `dist/`）。
2. 打开 **PowerXAdmin** 后台页面；
3. 在插件管理区选择“从本地目录安装”；
4. 系统调用 **PowerX Backend（px）** 完成插件安装与激活；
5. 插件在本地生效，可直接调试和修改。

**特征：**

* 不依赖 Marketplace；
* 适合开发阶段；
* 调试高效、反馈即时。

---

### 2️⃣ 离线打包上传模式

**目的**：
用于企业内网或无公网访问场景下的插件分发。

**流程：**

1. 开发者使用 `px-plugin pack` 打包插件，生成 `.pxp` 压缩包；
2. 管理员在 **PowerXMarketplace（px-market）** 页面选择“离线上传”；
3. Marketplace 校验并注册插件；
4. 管理员可在 PowerX Admin 后台查看并安装插件；
5. 启用后插件生效。

**特征：**

* 适合封闭环境；
* 支持人工审核；
* 便于内部插件流转。

---

### 3️⃣ 在线发布模式

**目的**：
用于正式的 Marketplace 插件分发和生态发布。

**流程：**

1. 开发者通过以下任一方式上传插件：

   * 使用命令行 `px-plugin publish`；
   * 或在 **PowerXPlugin 管理界面** 直接在线发布；
2. 插件上传至 **PowerXMarketplace（px-market）**；
3. Marketplace 进入审核流程；
4. 审核通过后，插件在市场中展示；
5. 所有 PowerX 实例（无论在线或离线）上线后可同步市场内容；
6. 用户可选择安装、启用插件。

**特征：**

* 标准化生态发布；
* 支持版本审核与签名；
* 自动通知与版本更新。

---

## 四、生态闭环

* **PowerXPlugin** (px-plugin工具)负责插件构建、打包与发布。
* **PowerXAdmin** 负责插件安装、启用与调试。
* **PowerX**（PowerX Backend）负责插件运行与生命周期管理。
* **PowerXMarketplace** 负责插件审核、上架与分发。

四者协作形成从开发到分发的完整生态闭环。

---

## 五、总结

PowerX Plugin 的三种用例覆盖了插件从**开发 → 调试 → 发布 → 分发**的全生命周期。
通过分工清晰的 CLI 工具链与统一接口标准，PowerX 实现了：

* 灵活的插件扩展机制；
* 支持离线与在线两种分发方式；
* 生态级的安全与审核流程。
