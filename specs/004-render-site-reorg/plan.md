# Implementation Plan: PowerX Docs Render Site Reorg

**Branch**: `[004-render-site-reorg]` | **Date**: 2025-10-21 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/004-render-site-reorg/spec.md`

**Note**: Generated via `/speckit.plan` following `.specify/templates/commands/plan.md`.

## Summary

Restructure the PowerX documentation site so `.vitepress` remains under `docs/` while all renderable content, localized mirrors, and public assets move into `docs/website/`. Preserve localization parity, navigation integrity, and build tooling, and introduce an AI驱动 whitelist workflow that proposes publish actions, requires human confirmation, and allows manual overrides for high-risk cases.

## Technical Context

**Language/Version**: TypeScript 5.9, Node.js 18 LTS  
**Primary Dependencies**: VitePress 1.6, TailwindCSS 3.4, PostCSS/Autoprefixer, internal localization scripts (`scripts/localization/*.mjs`)  
**Storage**: Git-tracked filesystem within `docs/`  
**Testing**: `npm run lint`, localization health scripts (`node scripts/localization/check-parity.mjs`, `node scripts/localization/review-guard.mjs`)  
**Target Platform**: Static documentation site generated by VitePress and deployed through PowerX Docs pipeline  
**Project Type**: Documentation static site (VitePress)  
**Performance Goals**: `npm run docs:build` completes without errors within existing CI budget (<5 min wall clock); locale navigation smoke tests observe zero 404s post-migration  
**Constraints**: Render root limited to `docs/website/`; AI publish suggestions need human confirmation and manual override path; reuse existing logging/audit capabilities; maintain compatibility with localization automation  
**Scale/Scope**: Entire public documentation corpus (~hundreds of markdown files plus localized mirrors); all localization manifests and review workflows must continue functioning after migration
