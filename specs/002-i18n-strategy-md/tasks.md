## Dependencies & Execution Order

### Phase Dependencies
- **Setup (Phase 1)** → prerequisite for Foundational work.
- **Foundational (Phase 2)** → must complete before User Story phases.
- **User Story Phases (3–5)** → can start after Phase 2; execute in priority order (US1 → US2 → US3) or in parallel if resources allow.
- **Polish (Phase 6)** → occurs after all targeted user stories finish.

### User Story Dependencies
- **US1**: Depends on Foundational tasks; no dependencies on other stories.
- **US2**: Depends on Foundational tasks; may read configuration touched by US1 but remains independently testable.
- **US3**: Depends on Foundational tasks and reuses the mirroring script produced in US1.

### Within Each User Story
- Shared utilities implemented first (e.g., mirroring script) before UI integration.
- UI/theme adjustments follow configuration updates.
- Validation tasks conclude each story to confirm independent functionality.

## Parallel Execution Opportunities
- Tasks marked with **[P]** (T004, T005, T006, T010, T011, T015, T018, T022, T023, T027, T029) can run in parallel once their prerequisites finish.
- Different user stories may proceed concurrently after Phase 2 if multiple contributors are available.
- Validation tasks (T014, T019, T028) should run after corresponding implementation tasks to close the feedback loop.

## Implementation Strategy
- **MVP Scope**: Complete all Phase 3 tasks (US1) to deliver an English-browsable site.
- **Incremental Delivery**:
  1. Finish Phase 1–2 to unlock localization tooling and workflow diagram.
  2. Ship US1 for English readers, including fallback handling and performance measurement.
  3. Layer US2 safeguards to protect Chinese defaults.
  4. Roll out US3 automation, review gating, and documentation updates.
  5. Execute Phase 6 polish before release handoff.
